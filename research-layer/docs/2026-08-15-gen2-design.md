# Composer gen-2 + Gauntlet protocol-v2 — design spec (2026-08-15)

A paired build: regime-capable composition AND a corrected edge-decay
measurement, both pre-declared before any gen-2 spec exists.

## Why paired

Gen-1's funnel closed at 22 → 13 → 0, with all 13 dying on the same gate:
per-trade edge decay of −56% to −73% against a −25% threshold. Every other
gate passed comfortably (OOS net positive, MC P05 2.2–4.5, P(ruin) ≈ 0,
DSR ≥ 0.99).

Measured on the committed data across the same fence, passive buy-and-hold
decayed *harder* than the strategies did:

| | IS CAGR (2017-08-17…2023-12-31) | OOS CAGR (2024-01-01…) | implied decay |
|---|---|---|---|
| BTCUSD | +43.2% (2020–21 alone: +153.0%) | +14.7% | −66% |
| ETHUSD | +37.3% (2020–21 alone: +429.0%) | −8.1% | −122% |

Annualized vol also collapsed: BTC 74.6% → 47.1%, ETH 94.5% → 67.7%.

All 13 specs were long-biased, so their per-trade edge scales with drift and
vol — both of which fell hard. The v1 gate has no benchmark and no volatility
normalization, so it cannot distinguish "this strategy was overfit" from "the
opportunity set shrank." On this asset class across this fence, −25% absolute
decay is close to structurally unpassable for anything long-biased, including
a strategy behaving exactly as designed. Composition changes alone would very
likely reproduce the zero.

**Legitimacy.** Gen-1's verdicts stand; the 13 stay in `graveyard`, which is
terminal. This spec does not re-judge them. It fixes a measurement that
demonstrably conflates two different things, and every rule below is chained
before a single gen-2 spec is registered. The v2 note states openly that the
flaw was identified from gen-1's results — that is ordinary science, and
hiding the provenance would be the dishonest version.

Coen-approved decisions:

| Decision | Choice |
|---|---|
| Scope | Paired: composition + `gauntlet-protocol-v2` |
| Decay measurement | Vol-normalized per-trade edge (not benchmark-relative — benchmark edge crosses zero OOS on ETH, making ratios unstable) |
| Resurrection guard | Exact-composition fingerprint block + cumulative DSR trial count |
| Composition | Additive grammar (short-capable types) + mandatory regime hypothesis |
| Versioning | In-place edits, `PROTOCOL` bumped to v2; git history archives v1 |
| Re-judging gen-1 | NEVER on-chain. Off-chain diagnostic only, after v2 is chained, ratcheted |

## 1. Grammar additions (`pipeline/blocks.py`)

Three new types. Existing twelve are untouched — `register_block_type`'s
conflict guard refuses any changed `params_schema`, so growth is additive by
construction.

| role | type | params (grid) |
|---|---|---|
| entry | `trend_scan_ds` | max_lookback {60,90,120}, t_min {2.0,3.0}, direction {long, short, both} |
| entry | `ma_cross_ds` | fast {5,10,20}, slow {50,100,200}, direction {long, short, both} |
| regime | `regime_ma_short` | ma_len {100,200} |

`CONSTRAINTS` gains `("entry","ma_cross_ds")` → fast < slow (same lambda shape
as `ma_cross`).

**Executor semantics** (`entry_signals`, new branches — existing branches
unchanged):

- `trend_scan_ds`: same best-|t| window selection as `trend_scan`. Fires +1
  when best_t ≥ t_min (direction long or both), −1 when best_t ≤ −t_min
  (direction short or both). Long-only and short-only variants suppress the
  other side.
- `ma_cross_ds`: `state[i]` = +1 when SMA(fast) > SMA(slow), −1 when <, 0
  during warmup. Entry signal on a state change into a permitted direction
  (+1 if direction allows long, −1 if it allows short).
- `regime_ma_short` (in `gate_mask`): entries permitted while
  `close < SMA(ma_len)` — the mirror of `regime_ma`. `gate_mask` remains
  direction-blind; see the mutual-exclusion rule in §2.

**Simulator edit** (`simulate_asset`): the ma_cross signal-exit branch
currently reads `entry["type"] == "ma_cross" and state[i-1] == 0`. It becomes
type-set membership (`in ("ma_cross", "ma_cross_ds")`) with the condition
`state[i-1] != pos["side"]` — the position closes when the cross state stops
agreeing with the side it was opened on. For `ma_cross` (states 0/+1) this is
behaviorally identical to the current rule, so gen-1's screen artifacts remain
reproducible; a regression test pins that.

## 2. Composer changes (`pipeline/composer.py`)

**Composition fingerprint.**

```
composition_fingerprint(spec) = sha256(canonical_json({
    "assets": sorted(spec.universe.assets),
    "timeframe": spec.universe.timeframe,
    "blocks": sorted(spec.blocks, key=(role, type, canonical params)),
}))
```

Excludes `created_utc`, `run_id`, `name`, `family`, provenance — everything
that differs between two registrations of the *same strategy*.

**Two new validation rules** (families fail loudly, like any other invalid
family; both counted in the DROPPED summary):

7. **No resurrection.** Any expanded sibling whose fingerprint matches a
   previously-registered strategy (any state, including graveyard) or another
   sibling within this run → family rejected, reason names the colliding
   `strategy_id`.
8. **No empty regime.** A family carrying both `regime_ma` and
   `regime_ma_short` → rejected. `gate_mask` ANDs its gates, so the
   combination admits nothing and would silently produce a zero-trade spec.

Expressing "long above the MA, short below it" is therefore two specs, each
with its own regime hypothesis — not one spec that flips. A symmetric design
uses `direction: both` with no MA regime gate.

**Proposal schema + prompt.** `PROPOSAL_SCHEMA` gains a required
`regime_hypothesis` string per family. `SYSTEM_PROMPT` adds: the new block
types; a plain statement that gen-1's three families were all long-biased and
all failed because their edge scaled with a drift and volatility regime that
did not persist; and a requirement that each family state which regime it
expects to work in and why it is not merely levered beta.

**Where the hypothesis is recorded.** The strategy spec schema is
`additionalProperties: false` and must not change, so `regime_hypothesis` does
NOT enter the spec. It is printed in the Composer run output, and that output
is committed as `docs/runs/2026-08-15-composer-gen2.txt` in the same commit as
the registry write — git-timestamped alongside the specs it describes. Every
family's hypothesis is therefore on the public record even though it is not a
chained field.

## 3. Gauntlet protocol-v2 (`pipeline/gauntlet.py`)

`PROTOCOL = "gauntlet-protocol-v2"`. The existing guard already refuses a real
run unless a note starting with the compiled-in protocol string is chained, so
v2 code cannot run under v1's note.

**Gate (a2) — vol-normalized edge decay.** Trades attribute to IS/OOS by entry
date against the cutoff, as in v1. Each window's volatility is measured over
its *bars*, not its trades: IS vol from bars dated ≤ cutoff, OOS vol from bars
dated > cutoff, computed as the equal-weight mean across the spec's assets of
(daily log-return stdev × √365) over those bars. Then:

```
is_edge_norm  = is_edge  / is_vol
oos_edge_norm = oos_edge / oos_vol
edge_decay_pct = (oos_edge_norm - is_edge_norm) / abs(is_edge_norm) * 100
```

Gate: `edge_decay_pct > -25`, failing with reason `edge_decay` when
`is_edge_norm <= 0` (unchanged convention). All other gates and the fixed fail
order are unchanged: `oos_negative → edge_decay → mc_p05 → p_ruin → dsr →
cost_stress`.

**Metrics.** The eight SCHEMA keys are retained, with `is_edge_per_trade` /
`oos_edge_per_trade` / `edge_decay_pct` now carrying the normalized values.
Four keys are added (SCHEMA specifies minimums, so extras are permitted):
`is_edge_raw`, `oos_edge_raw`, `is_vol`, `oos_vol` — both readings on the
record, so anyone can recompute the v1 number from a v2 verdict.

**DSR trial count.** `N` = the count of every `strategy_registered` entry in
the chain at run time (gen-1's 22 + gen-2's batch), not the sibling group.
Variance across trials = sample variance of the full-run daily Sharpes of all
those strategies. Selection still awards one quarantine slot per *sibling
group* (unchanged) — the cumulative count changes only the deflation hurdle.

Expected effect: N = 12 → ~52 raises the Sharpe hurdle roughly 40%. Gen-1's
DSRs were ≥ 0.99, so this tightens honestly without being punitive.

## 4. Off-chain diagnostic (`research-layer/diagnose_protocol_v2.py`)

A committed, standalone script that loads the graveyarded gen-1 strategies,
computes what they would score under v2's gates, and writes a report to
stdout plus `docs/diagnostics/2026-08-15-v1-under-v2.txt`.

**It imports nothing that writes.** No `Registry.record_*` call, no
`--registry` write path, not a flag on `gauntlet.py`. There is deliberately no
friendly-run mode to be tempted by.

Run only *after* the v2 note is chained, never before — computing v1 outcomes
under a candidate rule while still choosing the rule would make it impossible
to prove the rule wasn't tuned until something survived.

**Ratchet rule** (stated in the v2 note): the diagnostic may only tighten v2,
never loosen it, and any change requires a fresh pre-declared note. Its result
is published as a chained `note` regardless of outcome. If it shows v2 would
have passed most of the 13, the gate has lost its teeth and must be tightened
before gen-2 runs.

The 13 remain in `graveyard` permanently either way. The script exists to
audit the gate, not to rescue specs.

## 5. Disclosed limitation

The 2024+ holdout is no longer virgin: gen-1 consumed it once, and gen-2 is
designed with knowledge of what that run showed. Cumulative trial counting is
a partial mitigation, not a cure — the only complete fix is waiting for new
data. This is stated in the v2 note rather than buried here.

## 6. Sequencing

1. Build and test everything (offline, no chain writes).
2. Chain the `gauntlet-protocol-v2` note.
3. Run `diagnose_protocol_v2.py`; publish the result as a chained note; apply
   the ratchet if it fires.
4. Composer gen-2 `--dry-run` → Coen's batch gate → real run.
5. Screen — `screen-protocol-v1` unchanged, training fence still 2023-12-31.
6. Gauntlet `--dry-run` → Coen's batch gate → real run.

Steps 2–6 each verify the chain and commit before the next.

## 7. Testing (offline)

- New executors: hand-computed short-side signals for `trend_scan_ds`
  (best_t ≤ −t_min fires −1) and `ma_cross_ds` (state flip into a permitted
  direction); direction filtering suppresses the disallowed side; `both`
  fires either.
- `regime_ma_short` admits below the MA and blocks above, mirroring
  `regime_ma`; warmup still blocks.
- Simulator: `ma_cross` behavior byte-identical under the rewritten
  signal-exit condition (regression); `ma_cross_ds` short position closes on
  state flip.
- Fingerprint: identical composition → identical fingerprint regardless of
  asset/block ordering, `created_utc`, `run_id`, `name`, or `family`;
  any param change → different fingerprint.
- Rule 7: a family re-proposing a registered composition is dropped with the
  colliding id named; a within-run duplicate pair is dropped.
- Rule 8: `regime_ma` + `regime_ma_short` dropped.
- Vol-normalized decay: a case where raw decay fails but normalized passes
  (vol collapse only), and a case where normalized fails but raw passes
  (edge fell faster than vol) — both hand-computed.
- DSR: trial count equals the registry-wide strategy count, not the group's.
- Protocol guard: a chain carrying only the v1 note does NOT satisfy v2.
- Diagnostic script: has no import path to a registry writer (asserted by
  source inspection in a test); produces a report from a fixture chain.
- Live-chain regression: the current 1,554-entry registry still validates.

## Out of scope

Cross-asset relative-value / pair blocks (the engine books each asset
independently; coordinated two-leg positions are a genuine engine build, and
the enlarged corpus's triangulated stat-arb material deserves its own cycle).
Quarantine wiring. Any change to `screen.py`'s gate or fence. Any touch of the
root forward-test log.
