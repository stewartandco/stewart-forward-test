# Composer gen-3 + Gauntlet protocol-v3 — design spec (2026-08-16)

Protocol-v3 corrects one thing: how multiple-testing trials are counted and
how their dispersion is measured. Everything else in the battery is
unchanged, the grammar is unchanged, and all 56 previously registered
strategies stay in `graveyard`, which is terminal.

## Why v3 exists

Protocol-v2 set the DSR trial count to every `strategy_registered` entry in
the chain, with V[SR] as the sample variance of those strategies' observed
daily Sharpe ratios. Measured against the real registry, that makes the gate
unpassable by anything this system can produce:

| `trials_n` | SR\* hurdle (annualized) | Best strategy ever registered (SR 1.42) clears it? |
|---|---|---|
| 12 (v1, per sibling group) | 1.34 | yes |
| 22 | 1.56 | no |
| 56 (v2, at gen-2's run) | 1.86 | no |
| 90 (where gen-3 would land) | 2.00 | no |

Across 56 registrations the best daily Sharpe achieved is 0.0743 (annualized
1.42), while the v2 hurdle stood at 1.86 and rises with every registration.
Generation 3 under v2 could only produce a survivor by generating a
daily-bar crypto strategy above roughly 2.0 Sharpe net of costs. A gate that
returns `fail` regardless of merit is not strict; it is not measuring.

**The specification error, stated plainly.** Bailey & López de Prado's
deflation requires V[SR] to be the dispersion of trial Sharpe ratios *under
the null*. v2 used the sample variance of 56 observed Sharpes drawn from four
structurally different strategy families, which folds genuine differences in
expected return into a term that is supposed to represent sampling noise.
The perverse consequence is that proposing a *more varied* search raises the
bar on its own winner. The correction is the one the literature already
prescribes and that this registry already holds as an accepted card (L6,
Backtest Statistics): cluster correlated trials, count effectively
independent ones, and take dispersion across clusters.

**Legitimacy.** This change loosens the DSR gate, and we already know which
buried strategies it would have helped. What makes it defensible rather than
goalpost-moving:

1. The justification is structural and outcome-independent — a gate no
   achievable strategy can pass measures search volume, not skill.
2. The method is prescribed by literature already accepted into this
   registry, not invented for the occasion.
3. The 56 stay buried. Nothing is re-judged, nothing returns.
4. The chosen algorithm's output (K) is **not knowable before running it**,
   so it cannot have been tuned toward a desired answer.
5. The v3 note records all of the above, including that the flaw was
   identified from gen-2's results.

Coen-approved decisions:

| Decision | Choice |
|---|---|
| Scope | Protocol-v3 (DSR trial counting only) + composition via prompt; grammar untouched |
| Trial count | Effective independent trials by clustering, per LdP / card L6 |
| Algorithm | Average-linkage agglomerative on correlation distance; K by silhouette quality |
| Composition | Grammar unchanged; prompt carries gen-2's outcomes as evidence |
| Buried strategies | Stay buried; no resurrection, fingerprint guard unchanged |

## 1. `pipeline/cluster.py` — deterministic effective-trial clustering

Pure stdlib, no randomness, no global state. Determinism is a hard
requirement: this gate must be reproducible by anyone auditing the repo, and
an algorithm whose output depends on initialization would fail that test.

| Function | Behavior |
|---|---|
| `correlation(a, b)` | Pearson correlation of two equal-length return series; returns 0.0 if either has zero variance |
| `distance(rho)` | `sqrt(0.5 * (1 - rho))` — LdP's correlation distance; ρ=1 → 0, ρ=0 → 0.707, ρ=−1 → 1 |
| `distance_matrix(returns_by_id)` | `{(id_i, id_j): d}` for all pairs, ids sorted |
| `agglomerate(ids, dmat)` | Average-linkage merge history. At each step merge the closest pair of clusters; **ties broken by the lexicographically smallest `(min_id_a, min_id_b)` pair**, so results are independent of input ordering |
| `labels_for_k(history, ids, k)` | Cluster assignment `{id: cluster_index}` at K clusters |
| `silhouette(labels, dmat)` | Standard silhouette per point; a point alone in its cluster scores 0.0 by convention |
| `effective_trials(returns_by_id)` | Returns `(k, labels, cross_cluster_variance)` |

`effective_trials` selects K over the range 2..n−1 by maximizing the
silhouette **quality score** `mean(S) / stdev(S)` — the criterion named in
card L6 — and falls back as follows:

- `n == 0` → `(0, {}, 0.0)`
- `n == 1` → `(1, {id: 0}, 0.0)` — sample variance is undefined for one point
- `n == 2` → `(2, {id_a: 0, id_b: 1}, sample variance of the two Sharpes)`;
  no clustering claim is made for one or two series

K is searched over 2..n−1 rather than 2..n because K=n places every series in
its own singleton cluster, where by convention every silhouette is 0.0 and
the quality score is undefined.
- if every candidate K yields `stdev(S) == 0`, K is the one with the highest
  `mean(S)`, ties broken by smallest K

**Cross-cluster variance**: each cluster's representative Sharpe is the mean
daily Sharpe of its members; the returned variance is the sample variance
(n−1 denominator) across those K representatives, or 0.0 when K < 2.

## 2. Protocol-v3 gauntlet (`pipeline/gauntlet.py`)

`PROTOCOL = "gauntlet-protocol-v3"`. The existing guard already refuses a
real run unless a chained `note` starts with the compiled-in protocol
string, so v3 code cannot run under v2's note.

In `run()`, the loop that computes every registered strategy's full-run daily
returns is unchanged. What changes is what happens to those series: instead
of `trials_n = len(all_srs)` with variance across all of them, the series are
passed to `effective_trials`, and K plus the cross-cluster variance feed
`expected_max_sharpe`.

`evaluate_spec`'s gate logic is unchanged — the only functional difference is
which numbers arrive as `trials_n` and `trials_sr_var`. Its signature gains
one parameter, `registered_n`, carried straight through to the metrics dict
so a verdict shows both counts. Metrics gain one key:

- `trials_n` — the count actually deflated against; under v3 this is K
- `registered_n` — the raw number of registered strategies (NEW)

Both appear in every verdict so the change is legible on the chain rather
than implied. The full cluster assignment `{strategy_id: cluster_index}` is
written into each artifact bundle's `config.json`, keeping chained metrics
compact while making the clustering fully auditable and reproducible.

Everything else is identical to v2: gates (a1) OOS net > 0, (a2)
vol-normalized edge decay > −25%, (b) MC P05 > 1.0, (c) P(ruin) < 5%, (d)
DSR ≥ 0.95, (e) OOS net > 0 at 2× slippage; the fixed fail order
`oos_negative → edge_decay → mc_p05 → p_ruin → dsr → cost_stress`; two-phase
writes; orphan detection; one quarantine slot per sibling group by DSR with
lexicographic tie-break.

## 3. Composer (`pipeline/composer.py`)

The block grammar is **unchanged** — fifteen types, no additions. Only
`SYSTEM_PROMPT` changes, gaining generation 2's measured outcomes stated as
evidence rather than instruction:

- Four families were registered; all four were short-capable or symmetric,
  correcting generation 1's long-only bias.
- `forced_flow_overshoot_reversion` (symmetric z-score reversion) lost 46% to
  66% in training and failed the screen outright.
- `downtrend_short_only` produced only 10–19 trades in seven years and failed
  the screen's trade-count floor, not its P&L gate.
- Of the 18 that reached the gauntlet, 11 showed *positive* volatility-
  normalized edge decay out of sample — the two-sided trend and breakout
  designs held their edge per unit of opportunity.
- Every one of the four worst ruin and Monte Carlo outcomes came from
  `vol_target` sizing.

The prompt does not tell the model what to conclude from these facts.

## 4. Diagnostic and ratchet

`diagnose_protocol_v2.py` already reads `PROTOCOL` from the gauntlet module
rather than hardcoding a version, so it audits whatever the code currently
implements. It is renamed `diagnose_protocol.py` with an updated docstring;
behavior is otherwise unchanged, including having no registry write path.

Run it only **after** the v3 note is chained. Publish the result as a chained
note regardless of outcome.

**Ratchet for v3** (stated in the note): v3 is expected to loosen the DSR
gate relative to v2 — that is its purpose. The check is whether it loosened
too far. If a **majority of the 56 buried strategies would now pass**, that
is evidence the correction overshot, and v3 must be tightened with a fresh
pre-declared note before generation 3 composes anything. The 56 remain
buried in every case; this audits the gate, not the strategies.

## 5. Disclosed limitations

- The 2024+ holdout has now been consumed twice (gen-1 and gen-2). Effective-
  trial counting mitigates repeated search less than raw counting did, which
  is the point of the correction but also weakens that particular protection.
  A genuinely clean holdout requires waiting for new data.
- Clustering is computed over *all* registered strategies including
  graveyarded ones, so the effective-trial count reflects the full search
  history, not just the current batch.
- K is data-dependent: adding strategies can raise or lower it. The value
  used is recorded in every verdict and its assignment in every artifact.

## 6. Sequencing

1. Build and test (offline; no chain writes).
2. Chain the `gauntlet-protocol-v3` note.
3. Run `diagnose_protocol.py`; publish the result as a chained note; apply the
   ratchet if a majority would pass.
4. Composer gen-3 `--dry-run` → Coen's batch gate → real run.
5. Screen (`screen-protocol-v1`, unchanged) → Coen's gate → real run.
6. Gauntlet v3 `--dry-run` → Coen's gate → real run.

Each step verifies the chain and commits before the next. The concurrent
Reader v2 scanner shares this working directory and git index: stage and
commit atomically in a single command, and confirm no scanner writes are in
flight before any chain write.

## 7. Testing (offline)

- `correlation` on hand-computed series including the zero-variance guard;
  `distance` at ρ ∈ {1, 0, −1}.
- `agglomerate` on a synthetic matrix with two tight, well-separated groups
  recovers those groups at K=2.
- **Order independence**: permuting the input id order yields identical
  cluster membership.
- Tie-break determinism: a matrix with two equidistant candidate merges
  resolves the same way on every run.
- Perfectly correlated series (a sibling sweep) collapse to K=1 when that
  maximizes quality, and the returned variance is 0.0.
- Degenerate paths: n=0, n=1, n=2.
- `silhouette` on a known two-cluster case; singleton scored 0.0.
- `effective_trials` returns a variance strictly smaller than the naive
  all-strategy variance on a fixture with correlated siblings — the property
  that makes v3 differ from v2.
- Gauntlet integration: verdicts carry both `trials_n` (=K) and
  `registered_n`; artifact `config.json` carries the cluster assignment.
- Live-chain regression: the current 1,985-entry registry still validates.

## Out of scope

Cross-asset relative-value blocks (engine work for coordinated two-leg
positions). Grammar changes of any kind. Quarantine wiring. Any change to
`screen.py`. Any re-judging of the 56 buried strategies, by any mechanism.
